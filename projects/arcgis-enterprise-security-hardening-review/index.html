ArcGIS Enterprise Security Hardening Review

Your Portal is on the internet whether you meant it to be or not. Answer fourteen questions drawn from Esri's own security best practices, and this review names the gaps ranked by severity, the three fixes that matter most, and the score your deployment earns.

Runs entirely in your browser. No backend, no API key, no account. The checks come from Esri's security best practices documentation and the portalScan.py checks Esri ships with Portal (PS01 to PS08), and each one is named on the page. Nothing you type is sent or stored anywhere. Answer honestly, and answer Not sure when you do not know, because a gap you have not checked is still a gap.

How the review is scored

  1. Fourteen checks, weighted by severity. Critical checks are worth 10 points each, Important checks 8, Recommended checks 4. That adds up to 100.
  2. Yes earns the full weight, Not sure earns half, No earns nothing. Not sure is honest, and it is scored honestly: a check you have not verified is a check that might be open.
  3. One open Critical check drops the verdict a full band. A score of 90 with the proxy wide open is not Locked down. The verdict bands are 85 and above Locked down, 60 to 84 Fix the critical gaps first, and below 60 Hardening overdue.
  4. The three fixes that matter most come first. Open Critical checks outrank everything, then Important, then Recommended, so the order is the order to work in.
  5. portalScan.py does this check for real. Esri ships a Python script with Portal that scans the same ground and reports Critical, Important, and Recommended findings. Run it after this review, and treat its output as the authority over this page.

Sources: Esri, Security best practices, ArcGIS Enterprise documentation (enterprise.arcgis.com, security best practices page); Esri, Scan your portal for security best practices, ArcGIS Enterprise 11.0 documentation, portalScan.py checks PS01 to PS08 (proxy restrictions, token requests with credentials in the URL, services directory, HTTPS only, built-in account sign-up, anonymous access, LDAP identity store encryption, self-signed SSL certificate). Severity weights, verdict bands, the one-band downgrade, and the fix wording are planning rules from practice, not vendor numbers.

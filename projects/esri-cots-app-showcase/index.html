Esri COTS App Showcase

Your team does not need a custom app. It needs the right Esri app, configured well.

Three patterns cover most of what a GIS team is asked to build: a map with a list and a filter, an indicator board that answers a question at a glance, and a story that moves the map. Each one below is working, on the same live data, and each one maps to an Esri product you can build without writing code: ArcGIS Experience Builder, ArcGIS Dashboards, and ArcGIS StoryMaps.

Honest note: this page runs entirely in your browser. No backend, no API key, nothing you enter leaves this page. The data is Esri Living Atlas USA wildfire incidents, queried live from ArcGIS Online. A single query returns at most 1,000 features, so the counts below cover the 1,000 largest incidents by acres. A real Dashboard would query the full service.

Which app for which job

Pick the pattern by the question, not by the tool. The tool follows.

Experience Builder

Find it, filter it, open it

Someone needs to look at features one by one. A map, a list, a search box, and a filter. That is the Experience Builder pattern.

Dashboards

How are we doing, right now

Someone needs a number, not a map. Totals, averages, and a bar chart that updates with the data. That is the ArcGIS Dashboards pattern.

StoryMaps

Follow the story, the map follows you

Someone needs to understand what happened, in order. Chapters move the map and the numbers with them. That is the ArcGIS StoryMaps pattern.

Experience Builder pattern: current US wildfire incidents

Search by name, filter by state or size, click a fire in the list and the map flies to it. This is the shape of most Experience Builder apps: a map widget, a list widget, and a filter, all reading the same layer.

In ArcGIS Online or Enterprise: Experience Builder, Map widget plus List widget plus Filter widget, on the Living Atlas USA Wildfires layer. No code. The list and the map stay in sync because they share one data source.

StoryMaps pattern: the season in six chapters

Six chapters: an overview, then one chapter per fire, each one a real fire from the live data. Step through them and the map moves with the story. This is the shape of a StoryMaps sidecar: a short text panel, a map that follows it, and the numbers that make each chapter concrete.

In ArcGIS Online or Enterprise: ArcGIS StoryMaps, Sidecar block, with a map action per chapter. The chapters below are generated from the five largest fires in the live data, so the story updates when the season does.

How to build each one, in ArcGIS Online or Enterprise

No custom code in any of these. That is the point. COTS first, code only where COTS runs out.

Experience Builder

Build the map, list, and filter app

Use it when people need to find a feature and open it. Permit lookups, asset inspections, incident lists, site finders.

  1. In ArcGIS Online or Enterprise, open Experience Builder and start from the Blank fullscreen template.
  2. Add the Map widget and connect it to your layer. Set the pop-up to show the fields people actually ask about, and nothing else.
  3. Add the List widget on the same layer, sorted by the field that matters, acres here, date or status in your case.
  4. Add the Filter widget, one clause per question people ask: state, size, status. Keep it to three or four clauses.
  5. Connect the widgets so selecting a list item highlights the feature on the map. Test it on a phone. If the list is unusable on a phone, the app is unusable.

ArcGIS Dashboards

Build the indicator board

Use it when someone needs a number at a glance, every day. Operations boards, program reporting, executive updates.

  1. In ArcGIS Online or Enterprise, create a Dashboard and add the layer as the data source.
  2. Add Indicator widgets for the four numbers that decide the conversation: total, largest, average, and the one that shows risk.
  3. Add a Serial Chart widget grouped by the category that explains the total, state here, region or program in your case.
  4. Add a List widget for the top ten, so the board answers both "how much" and "which ones".
  5. Set the refresh interval to match how fast the data changes, and put the data source and the date on the board. A number without a source is a rumour.

ArcGIS StoryMaps

Build the story that moves the map

Use it when the order matters. A season, a project, a migration, a before and after. People remember a story; they forget a dashboard.

  1. In ArcGIS Online or Enterprise, create a StoryMap and draft the story in five or six chapters before you touch the map.
  2. Use a Sidecar block. One chapter, one map action: pan, zoom, and turn layers on or off to match the words.
  3. Keep each chapter under 80 words. The map does the explaining; the text only says what to look at.
  4. End with a chapter that says what happens next and who to contact. A story without a next step is a dead end.
What this demo simplifies. A real Experience Builder app would add authentication, a hosted feature layer with editing rules, and a proper pop-up design. A real Dashboard would use Arcade expressions and a scheduled refresh. A real StoryMap would use your own web maps, not a demo layer. None of that changes the pattern. The pattern is the decision, and the pattern is what this page shows working.

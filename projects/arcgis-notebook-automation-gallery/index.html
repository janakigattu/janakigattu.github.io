Nobody schedules a meeting to check for duplicate IDs. That is exactly why a notebook should do it at 2 a.m.

How this gallery works, honestly: each notebook below runs for real, here in your browser, on a small sample dataset. The checks, the counts, and the log are computed live, not printed from a screenshot. The Python next to each one is the skeleton that runs the same job on your own Portal or ArcGIS Online, on ArcGIS Notebook Server. There is no server here, no API key, and nothing you run leaves this page.

The week, at a glance

Four notebooks, four schedules. The nightly and six-hourly jobs run every day; the audit runs Monday morning; the health report runs on the first of the month.

Built on the ArcGIS Notebook Server scheduler: from Enterprise 10.8.1 you can create a task that runs a notebook on a recurring schedule, from once per minute to once every five months, with no one watching it.

The four notebooks

Notebook 01

Nightly Data QA Check

Runs daily at 02:00 · 12 asset records in the sample

Every edit that lands in the asset layer gets checked overnight: records with no geometry, required fields left blank, duplicate IDs, and edits older than 180 days that nobody has touched since. The notebook writes the failures to a QA table and emails the count, so the morning starts with a list instead of a surprise.

Replaces: the monthly manual spot-check that always found the same problems three weeks too late.

Show the Python skeleton 
from arcgis.gis import GIS

gis = GIS("home")
layer = gis.content.get("YOUR_ASSET_LAYER_ITEM_ID").layers[0]
rows = layer.query(where="1=1", out_fields="*", return_geometry=True).features

missing_geom = [f for f in rows if f.geometry is None]
blank_status = [f for f in rows if not f.attributes.get("STATUS")]
seen, dup_ids = set(), []
for f in rows:
    asset_id = f.attributes.get("ASSET_ID")
    if asset_id in seen:
        dup_ids.append(asset_id)
    seen.add(asset_id)

Swap in your layer item id and field names, then schedule it from the Tasks pane in the notebook editor. A scheduled run takes no input while it runs, so keep every value it needs in parameters.

Notebook 02

Weekly User and Content Audit

Runs Mondays at 07:00 · 10 users and 8 items in the sample

Once a week the notebook lists members who have not signed in for 90 days, items that were never shared, and items with no views in 180 days. Those three lists are the start of every access review: dormant accounts get disabled, unshared drafts get shared or deleted, and stale content stops confusing the search results.

Replaces: the annual clean-up that everyone agrees to do and nobody does.

Show the Python skeleton 
from arcgis.gis import GIS
from datetime import datetime, timedelta

gis = GIS("home")
cutoff = datetime.now() - timedelta(days=90)

dormant = []
for user in gis.users.search(max_users=500):
    last = user.last_login
    if last is None or last < cutoff:
        dormant.append(user.username)

for item in gis.content.search("owner:*", max_items=500):
    if not item.shared_with or item.num_views == 0:
        print(item.title, "| shared:", bool(item.shared_with))

Run it with a Publisher or Administrator account that can see all members and items. The notebook only reports; disabling an account is a separate, human decision.

Notebook 03

Scheduled Layer Sync

Runs every 6 hours · 14 source rows against 12 target rows in the sample

The field crew edits one layer; the public map reads another. Every six hours the notebook compares the two by ID and applies inserts for new rows, updates for changed rows, and deletes for retired rows, then reports exactly what changed. No one re-keys an edit, and the public map is never more than six hours behind the field.

Replaces: exporting a shapefile, emailing it, and hoping someone imports it before the next crew goes out.

Show the Python skeleton 
from arcgis.gis import GIS

gis = GIS("home")
source = gis.content.get("SOURCE_LAYER_ITEM_ID").layers[0]
target = gis.content.get("TARGET_LAYER_ITEM_ID").layers[0]

src = {f.attributes["ASSET_ID"]: f for f in
       source.query(where="1=1", out_fields="*").features}
tgt = {f.attributes["ASSET_ID"]: f for f in
       target.query(where="1=1", out_fields="*").features}

adds = [f for k, f in src.items() if k not in tgt]
updates = [f for k, f in src.items()
           if k in tgt and f.attributes != tgt[k].attributes]
deletes = [tgt[k].attributes["OBJECTID"] for k in tgt if k not in src]

target.edit_features(adds=adds, updates=updates, deletes=deletes)

Match on a stable business key, never on OBJECTID, because the two layers assign those independently. Log the counts every run so a bad sync is visible the same day.

Notebook 04

Monthly Service Health Report

Runs on the 1st of the month at 06:00 · 8 services in the sample

On the first of the month the notebook pulls uptime, average response time, and error counts for every service, flags any service below the 99.5 percent uptime target, and names the slowest one. The report goes to the platform owner before the month starts, not after a user reports a slow map.

Replaces: discovering a struggling service from a support ticket.

Show the Python skeleton 
from arcgis.gis import GIS

gis = GIS("home")
for server in gis.admin.servers.list():
    for service in server.services.list():
        status = service.status
        print(service.serviceName, "|", service.type,
              "| running:", status.get("realTimeState") == "STARTED")

# Uptime and response times come from ArcGIS Monitor metrics,
# or from the service statistics your team already collects.
# This notebook turns those numbers into the monthly report.

Pair it with ArcGIS Monitor for the uptime and response-time numbers. The notebook is the report writer, not the monitor.

How a scheduled notebook works

Four steps, all inside ArcGIS Enterprise. No custom server, no cron job on a desktop that someone switches off.

  1. Write the notebook in the notebook editor. Python, with the ArcGIS API for Python already available. Test it by running it once by hand.
  2. Declare the values it needs as parameters. Item ids, thresholds, email addresses. A scheduled run inserts those parameters as a cell at the top, like global variables.
  3. Create a task from the Tasks pane. Give it a title, pick the repeat type, and set the schedule. Available from Enterprise 10.8.1: a notebook can run once in the future or on a recurring basis, from once per minute to once every five months.
  4. Let it run with no one watching. A scheduled run opens a new container and runs without user control, so the notebook must not ask for input while it runs. Turn on Update Item on Completion if you want the notebook to keep its own results.
